# paicad 변경 기록

버전 정책: geometry-engine.md §17. `src/paicad/__init__.py`의 `__version__`이 단일 출처이고, `packages/paicad/**` 를 바꾸는 커밋마다 버전을 올리고 이 파일 최상단에 항목을 추가한다.

## 0.14.0 — 2026-10-26
### view grid
- 변경: 새 하위 명령 `paicad view grid --cad --features --cells --thumb-options --out-dir [--tag-dir --body-map --options --view-options --threads]`·`paicad shell view grid`(같은 인자 + 필수 `--fixed-dir`, `--tag-dir`는 받기만 함)(doe-preview.md §3, DP-C4·C5·C9). 한 프로세스에서 CAD·features·옵션 1회 적재 → 공칭 테셀레이션 1회(= `view export`/`shell view export --fixed-dir`와 같은 GLB, sha256을 `grid_manifest.nominal.view_sha256`) → 셀(`cells.json{schema_version, cells[{id ∈ [0-9a-z_]{1,64}, values}]}`, 빠진 이름 = 공칭)마다 입력 순서로 `view preview --fe off`와 같은 코드(update만, morph·check 없음)를 실행해 `cells/<id>/{preview_manifest.json, preview.glb(OK만), update/, thumb.png}`를 `cells/.part_<id>`에 쓴 뒤 rename. 셀 manifest·GLB = 같은 값의 `view preview --fe off` 출력과 바이트 동일(`timing` 제외, 맨 끝 추가 키 `thumb{file, sha256, w, h, clipped}`). 셀 상태: `OK`, `FAIL`(update 실패 코드 그대로 — 예 `GEOM_FEATURE_COLLISION`·`SHELL_FIXED_REGION_VIOLATION`), `ERROR`(`VIEW_*` = manifest + 공칭 회색 썸네일, 내부 예외 = `GEOM_INTERNAL`·셀 폴더 없음). 셀 하나의 실패는 다음 셀을 막지 않음. `grid_manifest.json` = envelope + `kind`·`camera{view_dir, center, scale, digest}`·`disp_range_mm`·`nominal{bbox, view_sha256}`·`cells[{id, status, code, category, max_disp_mm, total_s}]`·`timing{load_s, total_s}`(존재 = 성공, 종료 0에서만 씀). 종료코드: 0 모든 셀 처리, 3 입력 오류(`cells.json` 모르는 이름·비유한 값·중복/형식 오류 id·빈 목록, `thumb_options.json` 모르는 키·범위 밖, 출력 존재), 14 공칭 테셀레이션 실패(셀 처리 전), 20 내부. 셀 진행·결과는 `paicad.log`에 `[<id>]` 접두로만(stdout은 grid `PAICAD PROGRESS`/`RESULT`만). `thumb_options.json{schema_version, w·h 160~800(기본 320×240), view_dir(기본 [1,-1,1], up = Z), margin 1.0~2.0(기본 1.15), disp_range_mm [lo, hi](hi > lo), colormap "turbo16", nominal_ghost(기본 true), edges(기본 false)}`. 썸네일(`render.render_thumb`): 정사영 공통 카메라(`render.Camera.fit` — 중심 = 공칭 B-rep bbox 중심, 축척 = bbox 8꼭짓점 투영 크기 × margin이 화면에 맞게, 셀 형상과 무관), 흰 배경 → 공칭 엣지 연회색 1 px(nominal_ghost) → 셀 삼각형(z-버퍼, 음영 `_shade` + 카메라 기준 우상단 주광) 색 = 픽셀마다 정점 `_DISP_MM` 무게중심 보간값을 `turbo16`(16단계 고정 표 `render.TURBO16`)으로 `disp_range_mm`에서 양자화(범위 밖 끝 색 포화), FAIL 셀 = 공칭 회색 + `failure.features`의 moving 면(쉘 = 비드 바닥·플랭크·필렛) 빨강, `edges` = 셀 엣지 진회색 1 px(깊이 검사), 셀 정점이 화면 밖이면 `clipped: true`. camera digest = sha256(정렬 JSON{view_dir, center, scale, w, h}).
- 구조: `view preview`·`shell view preview` 본문을 값과 무관한 입력(`PreviewInputs`/`ShellPreviewInputs`)과 셀 처리(`preview_core`/`shell_preview_core`, 선택 `sink`)로 분리(기존 명령의 처리 순서·출력 불변), `update.values_from`·`shell.common.values_from`(= `load_values`의 검증, 파일 읽기 분리). `render.py`: 이미지 크기를 버퍼 모양에서 읽도록 `_raster`·`_raster_loop`·`_line`(색 인자 추가) 일반화, `_project`에 `size` 인자(기본 800×600).
- 영향: 기존 명령 인자·출력 불변 — 피처 PNG 바이트 동일(가상 쿠션 extract 28장·SM1 shell extract 20장을 0.13.0 코드 출력과 대조, 합성 바디 픽셀 digest 시험), 기존 paicad 시험 무수정 통과. 가상 쿠션 24셀(공칭 + 길이 파라미터 전부 층화 표본 23, 청크 4셀 × 6, 동시 2, `--threads 1`): 전체 27 s(목표 ≤ 90 s), 셀 평균 1.2 s(최대 2.9 s), 썸네일(래스터 + PNG) 약 0.07 s/셀, PNG 약 3 KiB·GLB 약 30 KiB/셀.
- 계약: doe-preview.md §3.1~§3.4·§9(V-DP-1·2·4·5·6·11 paicad 해당분 시험 `tests/test_view_grid.py`). 구현 해석(계약 반영 요청): `ERROR` 셀 중 `VIEW_*`는 셀 폴더(manifest + 회색 썸네일)를 남기고 내부 예외는 폴더 없음, `grid_manifest.nominal.view_sha256` = 공칭 `view export` GLB sha256(`--nominal-manifest` 인자 없음 — 셀 manifest `nominal_ref.view_sha256`은 null), 셀 manifest `thumb`는 `timing` 뒤 마지막 키, 빈 `cells` = 입력 오류, `shell view grid --tag-dir`는 받기만 함(쉘 update는 tag 미사용), `turbo16` 표는 paicad 상수 `render.TURBO16`(뷰어 범례가 같은 표 사용).
