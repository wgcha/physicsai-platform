## 17. S12 DOE 설계공간 지도 (사용자 결정 2026-10-17, D3-59)

목표: ④ 일괄 예측 결과(§14.8 B 오른쪽 칸)의 그래프 카드에 탭 **[변수–응답] [설계공간 지도]**를 둔다. 설계공간 지도 = run마다 변수 벡터(반영값)를 2차원에 투영(PLS 기본·PCA)하거나 평행 좌표로 펼치고, 점·선 색 = 고른 값(기본 "선택 커브의 최대값"). 표·커브 겹쳐보기와 같은 선택 모델(`selected` = doe_no)을 공유한다. 1·2·3차 원칙(설정만, AI 루트 읽기, 한국어, 필수 UI) 유지. 새 DB·새 작업 없음, 새 의존성 없음.

### 17.2 지표(metric) id — S12·S13 공용 문법

`fullmatch`, ASCII(D3-53). 계열 이름은 id에 넣지 않고 별도 `series`로 준다(계열 이름에 `:`·공백·한글 허용).

| id | 의미 | 값 출처 |
|---|---|---|
| `curve:max` / `curve:min` / `curve:absmax` | 고른 계열 y의 최대 / 최소 / max(\|max\|,\|min\|) (`series` 필수, 생략 = 그 배치 첫 계열) | run 하위 PREDICT `result.curve_artifact_id` → `curve.json`(§8.9 CURVE_PICK, 첫 `.xy` 파일의 계열들) |
| `resp:<NAME>_MIN` / `resp:<NAME>_MAX` | 원본 m_4 TCL이 쓴 `RESP:<NAME>_MIN|_MAX` 값(실패 줄은 값 없음) | `dirname(result.pred_h3d_rel)/RESPONSES.txt`(= `P/RESULT/`, §14.6) — `responses.read_responses` 재사용. `<NAME>`은 `response_defs.NAME_RE` |
| `tbl:<name>` | 결과 표 값(템플릿 stat 적용) | `predict_batch_runs.responses` — 그 배치에 `RESPONSES.txt`가 있는 성공 run이 하나도 없을 때만 목록에 나온다 |

정규식(`run_metrics.METRIC_RE`): `curve:(max|min|absmax)|resp:[A-Za-z][A-Za-z0-9_]{0,63}_(MIN|MAX)|tbl:[A-Za-z][A-Za-z0-9_]{0,63}`(옛 응답 이름이 이 규칙 밖이면 `tbl:` 목록에서 빠진다 — 경고 없음). 값은 유한 수만, 아니면 null.

### 17.3 공용 모듈 `physicsai_core/stage4_predict/run_metrics.py`(Impl-A 소유, S13은 import만)

```python
METRIC_RE: re.Pattern            # §17.2
@dataclass(frozen=True)
class RunFiles: curve_json: str | None; result_dir: str | None      # 절대경로(없으면 None)
@dataclass(frozen=True)
class RunMetrics:
    curve: dict[str, dict[str, float]] | None   # {계열: {"max","min","absmax","x_at_max","x_at_min","n"}}
    resp: dict[str, float] | None              # {"CornerStress_MAX": 1.5e2, …} (RESPONSES.txt 없으면 None)
def locate_run_files(conn, study_root: str, job: Mapping) -> RunFiles      # artifacts 행·result 키, resolve_in_study, 링크 거부
def load_run_metrics(files: RunFiles, *, max_bytes: int) -> RunMetrics      # 파일별 LRU(키 = 경로·mtime_ns·크기, 2048개, 잠금)
def metric_value(m: RunMetrics, metric_id: str, *, series: str | None, table: Mapping[str, Any] | None) -> float | None
def curve_stats(curve: Mapping) -> dict[str, dict[str, float]]             # 순수: NaN·무한·길이 불일치 계열 제외, 계열 ≤ 50
```
`curve.json`이 `ui.max_artifact_bytes`보다 크면 커브 없음(null). 계열 이름이 같은 계열이 여러 개면 첫 번째. 순수 함수 외 파일 I/O는 `load_run_metrics`만(시험에서 경로 주입).

### 17.5 계산 규칙(프런트 `designMap/linalg.ts`·`designMapData.ts`, 순수 함수)

1. **유효 run** = state SUCCEEDED이고 고른 값(metric·series)이 유한한 run. 제외 수는 사유별로 회색 한 줄: "제외: 실패·미완료 2 · 값 없음 1".
2. **유효 변수** = 유효 run에서 표준편차 > 1e-12·max(1, |평균|)인 파라미터. 상수 변수는 PCA·PLS에서 빼고 회색 "상수 변수 제외: RIB_N"(평행 좌표에는 평평한 축으로 남김).
3. 표준화 Z = (x − 평균)/표준편차(ddof=1), y도 같은 방식(PLS만).
4. **PCA**: 상관행렬 R = ZᵀZ/(n−1) → 대칭 Jacobi 고유분해(허용 1e-12, 최대 100 sweep) → 고유값 내림차순, 성분 2개. 축 라벨 `PC1 (X 분산 41.2%)` = λ_c / p_eff × 100. 부호: 각 고유벡터의 절댓값 최대 성분이 양수.
5. **PLS(기본)**: PLS1 NIPALS, 성분 a = min(2, p_eff, n−1). c마다 w = Zcᵀyc/‖·‖, t = Zc w, p = Zcᵀt/(tᵀt), q = ycᵀt/(tᵀt), Zc ← Zc − t pᵀ, yc ← yc − q t. 축 라벨 `PLS1 (X 28% · 값 63%)` — **X % = 그 성분이 설명한 표준화 변수 분산 비율** (tᵀt·‖p‖² / ‖Z₀‖²_F × 100), **값 % = 그 성분이 설명한 색 값 분산 비율** (q²·tᵀt / ‖y₀‖² × 100). 축 툴팁에 이 정의를 그대로 쓴다. 부호: corr(t_c, y) ≥ 0(0이면 |w| 최대 성분 양수) — "오른쪽·위로 갈수록 값이 큼".
6. **바이플롯 화살표**(토글 "변수 화살표", 기본 켬): 유효 변수 j마다 끝점 = (corr(z_j, t₁)·s₁, corr(z_j, t₂)·s₂), s_c = 0.9·max|t_c|, 끝에 변수 이름. 두 방법 공통 정의(구조 상관).
7. **평행 좌표**: 축 = 파라미터 전부(원 단위, 템플릿 순서) + 오른쪽 끝 값 축. 축마다 유효 run 최소~최대(위아래 5% 여백, 범위 0이면 ±0.5), 정수 축은 정수 눈금. 선 색 = 값. **값 축 브러싱**: 값 축에서 세로로 끌어 [lo, hi] → 범위 밖 선 불투명 0.12, 머리에 "값 120.0 ~ 150.0 · 7개 run", 더블클릭 또는 "범위 해제"로 해제(탭 안 상태, 저장 안 함).
8. **경계 조건**

| 상황 | PLS·PCA | 평행 좌표 |
|---|---|---|
| 유효 run < 3 | 회색 "점이 3개 이상 필요합니다(현재 n개)" | n ≥ 1이면 그림 |
| 유효 변수 0 | "모든 변수가 상수입니다" | 그림 |
| 유효 변수 1 | 방법 버튼 비활성 + 1D 산점(x = 그 변수 원 단위, y = 값) + "변수 1개 — 변수–값 산점도로 표시" | 그림 |
| PLS에서 y 상수(‖y₀‖ = 0) | PCA로 그리고 "값이 모두 같아 PLS를 계산할 수 없습니다 — PCA로 표시" | 그림(색 1개) |
| PLS 2성분째 ‖Zcᵀyc‖ < 1e-10·첫 성분 | 1D(x = PLS1, y = 값) + "두 번째 PLS 성분 없음" | — |
| 값 전부 같음 | 색 1개(색 막대 중간색), 색 막대 숫자 1개 | 같음 |

### 17.6 화면(필수 UI만)

- 그래프 카드(§14.8 "응답 그래프" 자리, 카드 위치·폭 그대로) 머리 = 탭 `변수–응답`(기존 내용 그대로) · `설계공간 지도`. localStorage `physicsai.stage4.batchGraphTab` = `response|map`(try/catch, 기본 response). 응답 정의가 없어도 설계공간 지도는 커브 값으로 쓸 수 있다.
- 설계공간 지도 머리 한 줄: 세그먼트 `PLS`(기본)·`PCA`·`평행 좌표` / "색 값" 드롭다운(§17.4 metrics, 기본 `curve:max`) / "커브" 드롭다운(curve 지표이고 계열이 2개 이상일 때만, 기본 첫 계열) / 체크 "변수 화살표"(PLS·PCA만). localStorage `physicsai.stage4.designMap` = `{method, metric, series, arrows}`(목록에 없는 값이면 기본으로).
- 그림: 자체 SVG(새 라이브러리 없음), 정사각 비율. 점 = 유효 run, 색 = 연속 색지도(viridis 9점 보간, 다크·라이트 공통) + 오른쪽 **세로 색 막대**(위 최대·아래 최소 숫자 `fmtNum`, 머리 = 지표 라벨·단위). 툴팁: `DOE #7 · run__00007` / 변수 `THK_1 2.31 · RIB_N 6` / `커브 최대값 152.3`. 점·선 클릭 = `setSelected(doe_no)`(결과 표 행 선택 + 커브 겹쳐보기 강조 — 기존 선택 모델), 선택 run = 강조색 테두리·맨 위.
- 커브 지표를 고르면 커브 겹쳐보기의 계열도 같은 계열로 바뀐다(선택 계열 상태를 `BatchResult`로 올림, 커브 겹쳐보기에서 바꿔도 지도가 따라감).
- 지도 아래 회색 한 줄: 제외·상수 변수 안내(§17.5) + "PLS: 색 값에 맞춰 축을 정합니다 · PCA: 변수 분포만으로 정합니다".

### 18.4 작업·step

job_type **`SURROGATE_OPT`**(stage 5, lane SLOT, 표시 "내장 최적화 반복", stage_label "⑤", `notify_success=False`). API `POST /jobs`로는 만들 수 없다(422 `INVALID_PARAMS` job_type) — 서비스·종료 훅만 만든다. params `{"surrogate_opt_id","opt_no","round":r}`(r = 1..). 반복 작업 r은 반복 0..r−1 자료로 적합하고 반복 r 후보를 낸다(r = iterations+1 또는 수렴이면 마무리만).

| step | kind(무게) | 처리 |
|---|---|---|
| SO_COLLECT | INTERNAL 10 "검증 결과 수집" | 반복 0..r−1 배치의 run 전부: 성공 run마다 `run_metrics`로 목적·제약 값, 반영값. 같은 설계(정수 변수 같고 연속 변수 \|Δ\| ≤ 1e-9·범위) 중복은 평균. 실패·값 없음 run은 "실패 설계" 목록(다시 제안 금지). `iter_{r-1:02d}/dataset.csv`(iter·batch·doe_no·run_key·변수…·objective·제약…·state) 작성. 반복 r−1의 `best_value`·`best_feasible`(r ≥ 2면 `improvement_rel`도) 기록. 탐색 개수 생략 시 기본 max(10, 4·d_free)(상한 `predict_batch.max_runs`). 정지 판정(§18.5) → 마무리면 SO_FIT은 품질 보고용으로만 돌고 SO_PROPOSE SKIPPED |
| SO_FIT | INTERNAL 45 "대리모델 학습" | §18.5 적합 + LOO. 제약마다 같은 종류 모델 1개 더. `iter_{r:02d}/surrogate.json`·`loo.csv`. 진행 문구 "대리모델 학습(GP) · 재시작 3/8" |
| SO_PROPOSE | INTERNAL 35 "후보 탐색" | §18.5 후보 k개 → `candidates.csv`. 진행 "후보 2/4" |
| SO_NEXT | INTERNAL 10 "검증 배치 등록·마무리" | 계속이면 **한 트랜잭션**(Study 행 FOR UPDATE, D3-25)에서 PREDICT_BATCH 부모 작업(QUEUED) + 배치·run 행 + `surrogate_opt_iters`(r, VERIFY) + opt `VERIFYING`·`iter_no=r`. 마무리면 `convergence.csv`·`verified_runs.csv`·`summary.json` 작성, opt `DONE`·`best`·`stop_reason`, 알림 `SURROGATE_OPT_DONE` 1건 |

- 검증 배치 params(서버 저장 형식 D3-51과 같고 키 1개 추가): `{batch_id, batch_no, param_set_id, model_id, multi_execution, template_kind, source:{kind:"table", row_count}, capture:{enabled:<opt.capture>}, surrogate_opt:{id, opt_no, iter_no}}`. 조합은 후보 값으로 만든 표 텍스트를 `batch_matrix.build_matrix_for({"kind":"table","text":…})`에 넣어 만든다(검증 규칙·정수 반영 재사용, batch_matrix 무수정). `surrogate_opt` 키는 `POST /jobs`에서 422(기존 추가 키 금지).
- 탐색 배치(새 DOE): 생성 API가 같은 트랜잭션에서 PREDICT_BATCH(`source.kind:"lhs"`, count·seed·ranges = 범위) + iters(0, EXPLORE) + opt `EXPLORING`. 재사용: iters(0, REUSE, 그 batch_id) + 반복 작업 r=1 바로 생성, opt `FITTING`. 재사용 배치는 최적화 소유가 아니다(취소·재시도 막지 않음).
- 정수 변수 = tpl 형식 `%Ni/%Nd`(`nearest.integer_vars`). 적합은 반영값으로, 후보 탐색은 `integrality`로 정수만 낸다(범위 lo = ceil, hi = floor, lo > hi면 422 `BOUNDS_INVALID`).

### 18.5 알고리즘(`physicsai_core/stage5_optimize/surrogate/`, 순수 numpy·scipy)

- 입력 정규화: 자유 변수(고정 아님 + 자료에서 상수 아님)를 범위로 [0,1]. 목적은 sense=max면 부호 반전해 최소화로 통일, 표준화(평균·표준편차).
- **GP(기본)**: 상수 평균(ordinary Kriging) + Matérn 5/2 ARD + nugget. 하이퍼파라미터(log 길이척도 ∈ [log 0.01, log 10], log nugget ∈ [log 1e-8, log 1e-1])는 집중 로그우도를 L-BFGS-B로, 시작점 `surrogate_opt.gp_restarts`(8)개(시드 LHS). Cholesky 실패 시 jitter 10배씩 3회, 모두 실패면 RBF로 바꾸고 경고 `GP_FALLBACK_RBF`. LOO = 닫힌 식(rᵢ = [K⁻¹y]ᵢ/[K⁻¹]ᵢᵢ, σ²ᵢ = 1/[K⁻¹]ᵢᵢ).
- **RBF**: cubic φ(r)=r³ + 1차 다항 꼬리, 평활 1e-10. LOO = Rippa 식(증강 행렬 역의 대각).
- 품질(반복마다 `fit`): `n_train, d_free, kind, loo_rmse`(목적 단위), `loo_nrmse`(= RMSE/std), `q2`(= 1 − PRESS/SS), 직전 반복 후보의 `pred_vs_verified_mae`(실제 표본 밖 오차). 화면 등급: q2 ≥ 0.9 좋음 · 0.7~0.9 보통 · < 0.7 낮음("탐색 run을 늘리세요").
- **후보 k개**: ① 활용 후보 = 대리모델 평균 최소(제약은 예측값 위반량 × 1e3 벌점). ② 나머지 k−1개: GP = EI × PoF(제약 GP의 정규 CDF 곱) 최대, kriging believer(고른 점에 예측 평균을 가짜 관측으로 더해 같은 하이퍼파라미터로 재적합 후 다음 점). RBF = 평균 최소 + 기존 자료·이미 고른 후보와 정규화 거리(√d로 나눈 유클리드) ≥ 0.1(못 찾으면 반으로, 0.0125까지). 탐색기 = `scipy.optimize.differential_evolution(seed=seed·1000+r, integrality=mask, maxiter=de_maxiter, popsize=de_popsize, vectorized=True, updating="deferred", polish=정수 없을 때만)`, 세대마다 `ctx.checkpoint()`(취소). 고정 변수는 탐색 벡터에서 빼고 그 값으로 채운다.
- 중복 제거: 기존 설계(성공·실패 포함)·이미 고른 후보와 같은 설계면 버리고 다음. 새 후보 0개 → 정지 `NO_NEW_CANDIDATE`.
- **정지(SO_COLLECT, r ≥ 2)**: best_t = 지금까지 검증된 최선(제약 만족 우선, 만족 설계가 없으면 위반량 최소 — `feasible:false`). improvement_rel = (best_{t−1} − best_t)/max(\|best_{t−1}\|, 1e-12)(최소화 기준). `improvement_rel < tol_rel` → `CONVERGED`, t = iterations → `MAX_ITER`. 반복 하나의 검증 run이 전부 실패 → opt FAILED `VERIFY_ALL_FAILED`. 유효 점 < max(5, d_free+2) → FAILED `TOO_FEW_POINTS` "유효 run이 n개뿐입니다(최소 m개) — 탐색 run 수를 늘리세요".
- 시간 한도: SO_FIT+SO_PROPOSE 합계 `surrogate_opt.fit_timeout_s`(600) 초과 → FAILED `SURROGATE_TIMEOUT`.
- 재현성: 같은 자료·설정·시드 → 같은 후보(같은 서버·같은 numpy/scipy 버전 기준, BLAS 부동소수 차이는 보장 밖). 시드는 `opt.json`·`surrogate.json`에 기록.

- 검증 422 `SURROGATE_OPT_INVALID` + problems(code ∈ `BOUNDS_INVALID`·`BOUNDS_OUT_OF_RANGE`·`TOO_MANY_VARIABLES`(자유 변수 > `max_variables` 20)·`NO_FREE_VARIABLE`·`EXPLORE_TOO_FEW`(count < max(5, d_free+2))·`EXPLORE_TOO_MANY`(> `predict_batch.max_runs`)·`METRIC_UNKNOWN`·`CONSTRAINT_INVALID`·`ITERATIONS_RANGE`·`CANDIDATES_RANGE`). 재사용 배치: 같은 Study·같은 템플릿·`DONE`·같은 모델(아니면 409 `BATCH_NOT_REUSABLE` + reason `NOT_DONE|TEMPLATE_MISMATCH|MODEL_MISMATCH`), 목적 지표가 있는 성공 run ≥ 최소 점수(아니면 `EXPLORE_TOO_FEW`). 그 밖 409 `SURROGATE_OPT_ACTIVE`·`FINAL_MODEL_REQUIRED`·`PREREQUISITE_MISSING`(PARAM_SET)·`FEATURE_NOT_AVAILABLE`(optimize_builtin false, `missing`)·`TEMPLATE_NOT_CONFIGURED`(템플릿 종류의 예측 기능 미구성), 404 `SURROGATE_OPT_NOT_FOUND`.
- 새 지표의 목적은 템플릿 응답 이름으로 만든 `resp:<NAME>_MIN|_MAX`, 또는 `curve:*`(series 생략 = 첫 계열). 새 DOE에서는 값이 있는지 미리 알 수 없으므로 SO_COLLECT에서 판정(`TOO_FEW_POINTS`).
- 최적화 소유 배치(params.surrogate_opt)에 `POST /predict-batches/{bid}/cancel`·`retry-failed` → 409 `BATCH_OWNED_BY_OPT` "내장 최적화 SO-001의 배치입니다 — ⑤에서 취소·이어서 실행하세요". 개별 하위 PREDICT의 기존 `/jobs/{id}/cancel`·`retry`는 그대로(배치 규칙대로 반영).
- `resume`: 실패 지점이 반복 작업이면 기존 재시도(새 작업, `current_job_id` 갱신), 배치 부모 실패면 내부적으로 retry-failed(가드 우회) — opt 상태를 그 단계(FITTING·VERIFYING·EXPLORING)로 되돌림.
- `/status.features.optimize_builtin`, `/status.surrogate_opt{defaults{iterations,candidates,tol_rel,surrogate}, max_variables, max_iterations, max_candidates}`.

### 18.7 종료 훅·취소·알림·자원

- `job_end`(모든 종료 경로): ① `batch_on_job_end`가 배치를 DONE으로 만들고 그 배치가 진행 중 opt의 iters에 있으면 → `PREDICT_BATCH_DONE` 알림 **생략**, 반복 작업 r+1(QUEUED, created_by = opt 등록자)을 넣고 opt `FITTING`. ② 최적화 소유 배치의 부모 PREDICT_BATCH 실패·중단 → opt FAILED `BATCH_FAILED`(기존 `JOB_FAILED` 알림 유지). ③ `SURROGATE_OPT` 작업 실패·중단 → opt FAILED `ROUND_FAILED`, 취소 → opt CANCELED. opt가 이미 종료면 훅은 아무것도 하지 않는다.
- 취소(`cancel`): opt를 **먼저** `CANCELED`(`stop_reason "CANCELED"`, finished_at)로 둔 뒤 같은 트랜잭션에서 비종료 반복 작업 취소 + 진행 중 배치에 기존 일괄 취소(부모·비종료 하위 전부, `cancel_active`). 끝난 run 결과·파일은 남는다. 알림 없음.
- 알림: `SURROGATE_OPT_DONE` 1건(등록자, job_id = 마지막 반복 작업) — 제목 "내장 최적화 SO-001 완료 — 최적 CornerStress_MAX 132.4 (반복 3 · 검증 12 run)", 본문 정지 사유 문구(수렴: "개선 0.4% < 기준 1%" · 최대 반복 · 새 후보 없음). 하위 PREDICT 알림은 §14.5대로 전부 억제, 반복 작업은 `notify_success=False`(실패는 `JOB_FAILED`).
- 자원: 반복 작업·배치 부모는 SLOT(FIFO, 대기열 1슬롯), 하위 PREDICT는 §14 그대로, 동시 입력 생성 수 = opt `multi_execution`(1~`train_data.max_multi_execution`). numpy 계산은 워커 프로세스 안에서 슬롯을 잡은 동안만.
- `progress_text`(서버 계산): `탐색 B-012 · 예측 완료 14/20` · `반복 2/3 · 대리모델 학습` · `반복 2/3 · 검증 B-014 예측 2/4` · `완료 — 수렴(개선 0.4% < 1%)` · `실패 — <사유 문구>` · `취소됨`.
- best(`surrogate_opts.best`)는 **검증된**(실제 예측 체인) 설계만. 대리모델 예측 최적값은 `summary.json`의 `surrogate_optimum`(참고)로만.

### 18.14 리스크

- **새 의존성 numpy·scipy**(~55 MB wheel, 사내 보안 검사·오프라인 수집). 없으면 기능만 꺼지고 나머지는 동작(`optimize_builtin=false`).
- **대리모델의 대리모델**: 목적값 자체가 PhysicsAI 예측이다. 최적 설계는 `PBS 검증 해석`(PREDICT_VERIFY)으로 실해석 확인을 권장(결과 화면 안내 문구).
- 예측 목적값의 잡음·불연속(형상 변화에 따른 메시 차이) → nugget·Q² 낮음 경고. 탐색 run 수가 적으면 후보 품질이 낮다(기본 탐색 수 = max(10, 4·d_free), 상한 `max_runs`).
- 소요: 검증 run 1개 = m_1~m_3 + 예측(수 분). 기본 3 × 4 = 12 run + 탐색 N. 대기열 FIFO라 다른 작업과 섞이면 길어진다(관리자 대기열 이동으로 조정).
- jobs 활성 인덱스 조건 변경(0010) — 최적화 배치가 수동 배치와 동시에 생성 단계에 있을 수 있음(입력 생성은 슬롯 1개라 실제 동시 실행은 아님).
- INTERNAL step 안 numpy BLAS가 순간적으로 여러 코어를 쓴다(슬롯 점유 중이라 다른 LOCAL 작업과 겹치지 않음, LIGHT 작업과는 겹칠 수 있음).
- 설계공간 지도: n이 작으면(< 10) PLS 축이 과적합 — 지도 아래에 n 표시. 첫 로드 시 API 스레드에서 파일 읽기(200 run 목표 < 5 s, E4-12-5).
